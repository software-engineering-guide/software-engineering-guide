# 5.0 บทนำส่วนที่ 5: การออกแบบยูไอยูเอ็กซ์

ส่วนนี้ว่าด้วยจุดที่ซอฟต์แวร์มาพบกับผู้ใช้ ซึ่งครอบคลุมหลายเรื่อง ตั้งแต่การวิจัยที่ช่วยให้เห็นว่าผู้ใช้ต้องการอะไร ส่วนติดต่อผู้ใช้และ[ระบบการออกแบบ](https://en.wikipedia.org/wiki/Design_system) (design system) ที่นำเสนอสิ่งนั้น ถ้อยคำที่นำทางให้ผู้ใช้ลงมือทำ [การเข้าถึงได้](https://en.wikipedia.org/wiki/Accessibility) (accessibility) และการรองรับหลายภาษาที่ทำให้ทุกคนใช้งานได้ ไปจนถึงงานวิศวกรรมฝั่งหน้าบ้านที่ส่งทั้งหมดนี้ไปสู่โลกจริงอันยุ่งเหยิงของเบราว์เซอร์และอุปกรณ์ต่างๆ เรามักอยากมองว่าทั้งหมดนี้เป็นของตกแต่งที่ใส่ตอนท้าย โปรดอย่าคิดเช่นนั้น เพราะนี่คือจุดที่งานต้นน้ำทั้งหมดจะไปถึงผู้ใช้หรือล้มเหลว และมันถูกตัดสินไว้นานก่อนที่หน้าจอสุดท้ายจะได้รับการขัดเกลา

สำหรับทีมขนาดใหญ่ การออกแบบผลิตภัณฑ์เป็นปัญหาของการประสานงานอย่างแท้จริง เมื่อหลายสิบสควอด (squad) ส่งงานเข้าสู่ผลิตภัณฑ์ร่วมชิ้นเดียว การตัดสินใจที่เป็นอิสระต่อกันจะสะสมจนยุ่งเหยิง เช่น ขั้นตอนซ้ำซ้อน คำศัพท์ขัดแย้งกัน ส่วนประกอบไม่สอดคล้องกัน และสายพานงานด้านภาษาที่ไม่มีใครรับผิดชอบ ทางแก้ในทุกบทของส่วนนี้มีรูปแบบเดียวกัน คือเปลี่ยนการตัดสินใจครั้งเดียวให้เป็นสินทรัพย์ร่วมที่มีธรรมาภิบาล เช่น persona ระบบการออกแบบ กลยุทธ์เนื้อหา กรอบงาน[การทำให้รองรับหลายภาษา](https://en.wikipedia.org/wiki/Internationalization_and_localization) (internationalisation หรือ i18n) ไลบรารีส่วนประกอบ และงบประสิทธิภาพ เพื่อให้หลายทีมที่ทำงานแยกกันยังรวมกันเป็นประสบการณ์เดียวที่สอดคล้องกัน

องค์กรขนาดใหญ่และภาครัฐทำให้เดิมพันสูงขึ้นอีก ซอฟต์แวร์องค์กรมักมีผู้ใช้ที่เลือกไม่ได้ พวกเขาจึงจ่ายราคาของการออกแบบที่แย่ในรูปของการฝึกอบรม ข้อผิดพลาด และภาระงานสนับสนุน แทนที่จะเลิกใช้ ส่วนบริการของรัฐเข้าถึงประชาชนทั้งประเทศ (รวมถึงคนที่อยู่ในภาวะวิกฤต ใช้อุปกรณ์เก่า ไม่มั่นใจในเรื่องดิจิทัล หรือไม่มีผู้ให้บริการรายอื่นให้เลือก) คุณภาพของการออกแบบจึงเป็นเรื่องของความเท่าเทียมและความไว้วางใจของสาธารณชน ในที่นี้ การเข้าถึงได้ไม่ใช่ของแถม แต่เป็นข้อบังคับทางกฎหมาย หน่วยงานรัฐต้องสร้างซอฟต์แวร์ที่ผู้พิการใช้งานได้ตามกฎหมาย และหน้าที่ด้าน[ภาษาที่เข้าใจง่าย](https://en.wikipedia.org/wiki/Plain_language)กับการเข้าถึงทางภาษาก็มักมีผลบังคับทางกฎหมายเช่นกัน

## บทต่างๆ ในส่วนนี้

- **5.1 พื้นฐานยูเอ็กซ์**: แนวปฏิบัติด้านการวิจัย การสร้างแบบจำลองผู้ใช้ และการคิดเชิงออกแบบ (design thinking) ที่ช่วยให้องค์กรตัดสินใจเรื่องผลิตภัณฑ์โดยอาศัยหลักฐานแทนการเดา และทำให้ทุกทีมมีแผนที่ของผู้ใช้ฉบับเดียวกัน
- **5.2 การออกแบบยูไอ และระบบการออกแบบ**: ฝีมือในการกำหนดสิ่งที่ผู้คนมองเห็นและสัมผัส รวมถึงระบบร่วมที่มีธรรมาภิบาลของโทเค็น ส่วนประกอบ และแพตเทิร์น ซึ่งทำให้หน้าจอนับพันของหลายทีมสอดคล้องกัน
- **5.3 การเข้าถึงได้**: การสร้างซอฟต์แวร์ที่ผู้พิการสามารถรับรู้ ใช้งาน เข้าใจ และใช้ประโยชน์ได้ โดยถือเป็นทั้งหน้าที่ตามกฎหมาย หน้าที่ทางจริยธรรม และการออกแบบที่ดีไปพร้อมกัน
- **5.4 การออกแบบเนื้อหา และการสื่อสาร**: การกำหนดถ้อยคำ ข้อความ และการสื่อสารที่ผลิตภัณฑ์ใช้เพื่อช่วยให้ผู้คนลงมือทำ ด้วยภาษาที่เข้าใจง่ายและน้ำเสียงที่สม่ำเสมอ เพราะถ้อยคำก็คือส่วนติดต่อผู้ใช้
- **5.5 การทำให้รองรับหลายภาษาและการปรับให้เข้ากับท้องถิ่น**: สถาปัตยกรรมที่ทำให้ซอฟต์แวร์ปรับตัวเข้ากับทุกภาษาและภูมิภาคได้ และขั้นตอนการแปลและปรับให้เหมาะกับวัฒนธรรมของแต่ละท้องถิ่น
- **5.6 วิศวกรรมฝั่งหน้าบ้าน**: การสร้างชั้นที่เผชิญกับผู้ใช้สำหรับสภาพแวดล้อมที่เราควบคุมไม่ได้ โดยใส่ใจเรื่องอายุการใช้งานของเฟรมเวิร์ก กลยุทธ์การเรนเดอร์ ประสิทธิภาพ และความยืดหยุ่น
- **5.7 การพัฒนาแอปพลิเคชันบนมือถือ**: การสร้างซอฟต์แวร์สำหรับอุปกรณ์มือถือ ครอบคลุมแนวทางเนทีฟ ข้ามแพลตฟอร์ม และโปรเกรสซีฟเว็บ แนวทางการออกแบบของแต่ละแพลตฟอร์ม ข้อจำกัดด้านการทำงานออฟไลน์ แบตเตอรี่ และความหลากหลายของอุปกรณ์ การเผยแพร่ผ่านแอปสโตร์ รวมถึงความมั่นคงปลอดภัยและการเข้าถึงได้บนมือถือ

- **5.8 การวิจัยการออกแบบและการทดสอบการใช้งาน**: การลดความเสี่ยงของการสร้างสิ่งที่ผิดด้วยการวิจัยเชิงสำรวจและเชิงประเมิน การเลือกวิธีที่เหมาะกับแต่ละคำถาม การทดสอบการใช้งานให้ดี การรับสมัครผู้เข้าร่วมที่เป็นตัวแทนของผู้ใช้จริง และการสังเคราะห์ผลที่เปลี่ยนการตัดสินใจได้จริง
- **5.9 การออกแบบบริการ**: การออกแบบบริการทั้งหมดที่ผู้คนได้รับผ่านหลายช่องทางและตลอดช่วงเวลา ทั้งหน้าฉากและหลังฉาก ด้วยแบบพิมพ์เขียวบริการ (service blueprint) และแผนที่เส้นทางผู้ใช้ (journey map) และทำให้องค์กรเดินไปในทิศทางเดียวกับบริการ ไม่ใช่แค่หน้าจอเดียว
- **5.10 การออกแบบการแสดงข้อมูลด้วยภาพ**: การเลือกแผนภูมิที่เหมาะกับคำถามและการเข้ารหัสข้อมูลอย่างซื่อตรง ด้วยหลักความเป็นเลิศทางกราฟิก จานสีที่เข้าถึงได้และปลอดภัยสำหรับผู้บกพร่องทางการมองเห็นสี และคำอธิบายประกอบที่ชัดเจน เพื่อให้แผนภูมิช่วยให้ตัดสินใจได้ ไม่ใช่ชักนำให้เข้าใจผิด

## บทเหล่านี้เกี่ยวข้องกันอย่างไร

บทเหล่านี้ร้อยเป็นเส้นเดียวจากความเข้าใจไปสู่การส่งมอบ พื้นฐานยูเอ็กซ์ (5.1) ระบุว่าผู้ใช้คือใครและกำลังพยายามทำงานอะไรให้สำเร็จ ยูไอและระบบการออกแบบ (5.2) ให้ความเข้าใจนั้นมีรูปลักษณ์ที่สอดคล้องกัน การออกแบบเนื้อหา (5.4) จัดหาถ้อยคำที่ถ่ายทอดมัน วิศวกรรมฝั่งหน้าบ้าน (5.6) ส่งผลลัพธ์ออกไป ส่วนการเข้าถึงได้ (5.3) และการทำให้รองรับหลายภาษา (5.5) ไม่ใช่ขั้นตอนแยกต่างหาก แต่เป็นคุณสมบัติที่ถักทอผ่านทุกบทที่เหลือ ประสบการณ์ที่เข้าถึงได้และแปลได้ต้องถูกออกแบบไว้ในส่วนประกอบร่วม แพตเทิร์นของเนื้อหา และโค้ดตั้งแต่ต้น ไม่ใช่มาแปะเพิ่มทีหลัง บทที่ 5.3 โดยเฉพาะพึ่งพาบทที่ 5.2 ให้แก้เรื่องการเข้าถึงได้ครั้งเดียวในแต่ละส่วนประกอบ และพึ่งพาบทที่ 5.6 ให้รักษาคุณสมบัตินั้นไว้ด้วยมาร์กอัปเชิงความหมายที่อิงมาตรฐาน

ส่วนนี้ยังเชื่อมโยงไปทั่วทั้งคู่มือ รูปแบบ "สินทรัพย์ดีกว่างานครั้งเดียว" ในที่นี้สะท้อนแนวคิดแพลตฟอร์มร่วมของบทที่ 8.4 (วิศวกรรมแพลตฟอร์มและประสบการณ์นักพัฒนา) และคุณค่ากับวิธีทำงานในบทที่ 1.1 และ 1.4 วางเงื่อนไขขององค์กรที่ทำให้การออกแบบสอดคล้องกันเป็นไปได้ตั้งแต่แรก การตรวจสอบการเข้าถึงได้ การถดถอยของภาพ (visual regression) และงบประสิทธิภาพควรอยู่ในสายพานการส่งมอบของบทที่ 8.1 (CI/CD และการส่งมอบ) เพื่อให้คุณภาพถูกบังคับใช้กับทุกการเปลี่ยนแปลง แทนที่จะตรวจกันก่อนเปิดตัวไม่นาน และการเฝ้าติดตามผู้ใช้จริง (ข้อมูลประสิทธิภาพที่เก็บจากอุปกรณ์และเครือข่ายของผู้ใช้จริง) ซึ่งประสิทธิภาพฝั่งหน้าบ้านต้องพึ่งพา ก็เชื่อมตรงกับแนวปฏิบัติด้านความสามารถในการสังเกตระบบในบทที่ 9.2 เมื่อทำได้ดี งานในส่วนนี้คือสิ่งที่ทำให้ระบบที่อธิบายไว้ในส่วนอื่นๆ ใช้งานได้จริงสำหรับผู้คนที่ระบบเหล่านั้นตั้งใจจะรับใช้
